# عقد استيراد المحتوى النظامي

المنصة تستورد **مقاطع مقطوعة سلفاً** لا ملفات تُقطَّع هنا. من أعدّ الملف عرف حدود المواد، وإعادة تقطيعها في المنصة تقصّ في منتصفها بلا وعي بها فيضيع ما بُني.

هذا العقد أربعة التزامات، ولكلٍّ منها فحصٌ يجري في `npm run check:legal` على الكود نفسه لا على وصفه.

---

## ١) الملف

| | |
|---|---|
| الصيغة | JSONL — سطر مستقل لكل مادة |
| الترميز | UTF-8 **بلا BOM** |
| نهاية السطر | `\n` أو `\r\n` |
| السطر الفارغ | يُتجاوَز |

**التقطيع التلقائي معطَّل في هذا المسار.** سطرٌ = مقطع، مهما طال أو قصر. ولا يمرّ المقطع المستورد بـ`chunkText` — تلك للوثائق التي تُرفَع ملفّاً فتُستخرَج نصّاً ولم يقطّعها أحد قبلنا.

> إن وُجدت علامة BOM أُسقطت وذُكرت في تقرير الاستيراد. تركها يجعل أوّل `id` مسبوقاً بحرف خفيّ لا يُرى، فينشئ نسخةً ثانية من المادة عند كل استيراد.

### الحقول

| الحقل | إلزامي | الاستخدام |
|---|---|---|
| `id` | نعم | **المفتاح الأساسي الفريد** — عليه يقع الاستبدال |
| `text` | نعم | **يُعرض ويُستشهد به** — ولا يُحوَّل إلى متجه |
| `embed_text` | نعم | **يُحوَّل إلى متجه** — ولا يُعرض ولا يُستشهد به |
| `law_id` | — | حصر البحث في نظام |
| `parent_law_id` | — | للائحة: معرّف نظامها، فتُجلب معه |
| `doc_type` | — | حصر البحث في نوع: `law` · `regulation` · `decision` · `circular` |
| `article_no` | — | استدعاء مادة بعينها |
| `instrument_no` | — | رقم الأداة النظامية — للعرض والاستشهاد |
| `status` | — | `active` · `amended` · `repealed` (الافتراضي `active`) — وتُقبل ألفاظها العربية، انظر أدناه |
| `is_repealed` | — | منطقيّ (الافتراضي `false`) |
| `law_title` | — | اسم النظام — للعرض والاستشهاد |
| `issue_date` | — | ميلادي — تُقرأ صيغه المتعارفة وتُوحَّد، انظر أدناه |
| `issue_date_hijri` | — | هجري كما ورد |
| `effective_from` · `effective_to` | — | ميلاديان، كسابقه |
| `source_url` | — | رابط المصدر الرسمي |

ما زاد عن هذه الحقول يُحفَظ كما ورد في `meta_json` ولا يُهمَل.

**مرادفات الحقول المقبولة:** `law_name` و`title` لـ`law_title` · `issue_date_g` و`date_gregorian` لـ`issue_date` · `issue_date_h` و`date_hijri` لـ`issue_date_hijri`.

**ألفاظ الحالة العربية** تُقابَل بالثلاثة المسجَّلة، وهي ترجمةٌ محصورة لا حالةٌ رابعة:

| يُكتب | يُخزَّن |
|---|---|
| ساري · سارٍ · سارية · نافذ · نافذة · معمول به | `active` |
| مُعدَّل · مُعدَّلة | `amended` |
| ملغي · ملغٍ · ملغى · ملغاة · منسوخ · منسوخة | `repealed` |

وتُطبَّع قبل المطابقة، فالتشكيل والهمزات والتاء المربوطة لا تُفرّق بينها.

**والتواريخ تُقرأ كما تُكتب ثم تُوحَّد** — رفضُ ملفٍ لأجل شرطةٍ مكان مائلة إتعابٌ بلا مقابل:

| يُكتب | يُخزَّن |
|---|---|
| `2005-09-27` · `2005/9/27` · `٢٠٠٥-٠٩-٢٧` | `2005-09-27` |
| `27/09/2005` · `27-09-2005` (يومٌ فشهر — العرف المحلي) | `2005-09-27` |
| `2005-09-27T00:00:00Z` | `2005-09-27` |

**وتاريخٌ هجريّ في حقلٍ ميلاديّ يُحفظ هجرياً ولا يُرمى.** سنةٌ دون ١٥٠٠ ليست ميلادية في نظام سعودي، فتذهب إلى `issue_date_hijri` ويبقى `issue_date` فارغاً — قيمةٌ صحيحة أُسيء وضعها، وكتابتها ميلادياً تجعل تاريخ الأداة كاذباً.

وما لا يُقرأ تاريخاً يبقى مرفوضاً برمزه: التساهل في الصيغة ليس قبولاً لكل شيء.

### مثال

```jsonl
{"id":"labor:74","law_id":"labor","doc_type":"law","article_no":"74","instrument_no":"م/51","status":"active","law_title":"نظام العمل","issue_date":"2005-09-27","issue_date_hijri":"1426/08/23هـ","source_url":"https://laws.boe.gov.sa/…","text":"ينتهي عقد العمل في الحالات الآتية: …","embed_text":"نظام العمل — المادة 74 — انتهاء عقد العمل: الحالات التي ينتهي بها العقد والإجراءات النظامية المقررة."}
{"id":"labor-reg:12","law_id":"labor-regulation","parent_law_id":"labor","doc_type":"regulation","article_no":"12","status":"active","law_title":"اللائحة التنفيذية لنظام العمل","text":"تُحسب مدة الإخطار وفق ما ورد في اللائحة.","embed_text":"اللائحة التنفيذية لنظام العمل — المادة 12 — احتساب مدة الإخطار."}
```

### ما يُرفض

سطرٌ يخالف العقد يُرفَض برقمه وسببه:

- `id` أو `text` أو `embed_text` ناقص — **ولا رجوع إلى `text` عند غياب `embed_text`**: الرجوع الصامت هو بعينه الخلط الذي يمنعه العقد، ولا يظهر أثره إلا كضعفٍ في جودة الإجابات.
- `status` خارج القيم الثلاث.
- تاريخ ميلادي بغير `YYYY-MM-DD`.
- `id` مكرّر داخل الملف نفسه — الاستبدال سيُبقي الأخير بصمت، وهو غالباً خطأ توليد.
- ملف مصفوفة JSON بدل JSONL.

**والافتراضي صارم:** سطرٌ واحد فاسد يوقف الدفعة كلها ولا يُكتب منها شيء. نظامٌ نصفه مستورد أسوأ من نظام لم يُستورَد.

**و«استيراد ما صحّ وتخطّي ما رُفض»** (`?partial=1`، ومربّع اختيار في الشاشة) لمن يعرف ما يتخطّاه: يُكتب الصالح، ويُعَدّ المتخطّى ويُذكر بأسبابه في العمود وفي جدول الأسباب. وحالة الملف تصير «استيراد جزئي» لا «تم الاستيراد» — تخطٍّ صامت يجعل نظاماً ناقصاً يبدو تامّاً.

### تقرير الرفض

الردّ يحمل `error_summary`: الأسباب **مجموعةً على كل الأسطر لا على المعروض منها**، ولكل سبب:

| | |
|---|---|
| `code` | رمزٌ ثابت للسبب — عليه يقوم التجميع لا على نصّ الرسالة |
| `count` | عدد الأسطر التي فشلت به — كلُّها، بلا سقف |
| `lines` | أمثلة من أرقام أسطرها |
| `keys` | **الحقول التي حملها السطر فعلاً** — بها يُعرَف الناقص بلا تخمين |

الرموز: `missing_id` · `missing_text` · `missing_embed_text` · `bad_status` · `bad_date:<الحقل>` · `duplicate_id` · `bad_json` · `json_array` · `not_object` · `long_id` · `long_text` · `long_embed_text`.

> ملفٌّ مولَّد بقالب واحد تفشل أسطره كلُّها بالسبب نفسه. ومئةُ رسالة متطابقة لا تقول أكثر مما تقوله واحدة، بينما «وأخطاء أخرى لم تُعرَض: ١٣١» تُخفي الحقيقة كلَّها. فالمطلوب: «١٨١ سطراً ينقصها `embed_text`، والحقول الموجودة فيها: `id` · `law_id` · `article_no` · `text`».

### أكثر من ملف

الشاشة تقبل اختيار عدّة ملفات معاً، وتستوردها واحداً بعد آخر وتذكر لكلٍّ حالَه.

**ووحدة «الكل أو لا شيء» هي الملف لا الاختيار كلّه:** نظامٌ نصفه مستورد أسوأ من نظام لم يُستورَد، أمّا نظامٌ سليم بجانب نظامٍ مرفوض فلا ضرر فيه. فيمضي الاستيراد إلى الملف التالي ولا يقف على أوّل مرفوض.

## ٢) الاستيراد استبدالٌ لا إضافة

المفتاح `id`، والكتابة `upsert`. إعادة رفع نظام محدَّث **تستبدل** مواده ولا تضاعفها.

بلا هذا يصير لكل مادة نسختان تتنافسان في نتائج البحث، ولا يظهر الخلل إلا كإجابةٍ تستشهد بنصّ قديم بلا سبب ظاهر.

ويقول التقرير أيّهما وقع: `inserted` جديدٌ لم يكن، و`updated` مادةٌ استُبدلت.

> `embed_text` الذي لم يتغيّر لا يُعاد تضمينه: تُقارَن بصمته فيبقى متجهه كما هو. وإعادة رفع نظامٍ عُدِّلت مادتان منه تُضمِّن مادتين لا الملف كلّه.

## ٣) الفهرسة: حقلان بدورين مختلفين

| | |
|---|---|
| يُحوَّل إلى متجه | `embed_text` **فقط** |
| يُعرض ويُستشهد به | `text` **فقط** |

خلطهما يعني إمّا ضعف الاسترجاع (لو حُوِّل `text` المجرّد) أو تلويث الاستشهاد بسياق زائد (لو عُرض `embed_text`).

ولذلك: `embed_text` لا يظهر في أعمدة أي استعلام عرض، ولا يقرؤه إلا `embedPending`.

### بناء `embed_text` عند غيابه

ملفٌّ أُعِدّ للعرض لا للاسترجاع يحمل النصّ ولا نصَّ تضمينٍ فيه. و`?build_embed_text=1` (أو مربّع الاختيار في الشاشة) يبنيه: **اسم النظام — المادة رقم** ثم النصّ.

وهذا ليس الرجوعَ الذي يمنعه العقد: ذاك تحويلُ `text` مجرَّداً إلى متجه، وهذا تركيبُ نصّ التضمين الذي يطلبه العقد. ومع ذلك:

- **معطَّل افتراضياً** ولا يقع إلا بطلبٍ صريح.
- **يُعَدّ ويُقال** في التقرير (`embed_text_built`) — بناءٌ صامت يجعل جودة الاسترجاع تتغيّر بلا أثرٍ يدلّ عليها.
- **`text` لا يُمسّ** — يبقى كما ورد، وهو وحده ما يُعرض ويُستشهد به.

وإعداد `embed_text` في المولِّد يبقى أفضل: هو الذي يعرف الباب والفصل وسياق المادة، والمنصة لا تعرف منها إلا ما في السطر.

**سقف مدخل المتجه ٨٠٠٠ حرف.** ما زاد يُقصّ **مدخل المتجه وحده** — المقطع يبقى مقطعاً واحداً ونصّه المعروض كاملاً كما ورد، ويُحصى ذلك في تقرير الاستيراد (`embed_text_truncated`).

**التضمين لا يُعطّل الاستيراد.** الكتابة إلى D1 هي العقد؛ يُضمَّن ما يسعه الطلب ويبقى الباقي معلَّقاً يصرّفه الـCron الليلي أو `POST /api/legal/embed-pending`. وبلا فهرس متجهي مهيَّأ يعمل البحث اللفظي وحده — استرجاعٌ أضعف، لا معطَّل.

## ٤) البحث: هجين مع تطبيع عربي

بحث دلاليّ على المتجهات **مع** بحث لفظيّ على النصّ، ودمج النتيجتين.

اللفظي ضروري لأن المستخدم يبحث برقم مادة أو مصطلح حرفي، والدلالي وحده يخذل فيها. ويُفهرس مع النصّ **مقبض المادة** — اسم النظام ورقمها ورقم أداتها — لأن رقم المادة قد لا يرد داخل نصّها أصلاً.

**التطبيع العربي شرط:** توحيد الهمزات (آ أ إ ٱ ← ا ، ؤ ← و ، ئ ← ي)، والتاء المربوطة (ة ← ه)، والألف المقصورة (ى ← ي)، وحذف التشكيل والتطويل، والأرقام غربية. وإلا فـ«الاجراءات» لن تطابق «الإجراءات».

ويُطبَّق على طرفَي المقارنة معاً: على النصّ عند الاستيراد وعلى الاستعلام عند البحث. وتُولَّد من كلمة الاستعلام صيغتاها — بأل التعريف وبدونها — فتطابق «إجراءات» «الإجراءات».

ولا يُطبَّع مدخل المسار الدلالي: النموذج يفهم الصرف العربي، والتطبيع يمحو منه ما يستفيد منه.

**الدمج بالرتب (RRF) لا بالدرجات:** درجة bm25 ودرجة التشابه الجيبي مقياسان مختلفان لا يُجمعان. ومطابقة رقم المادة ترفع النتيجة بقدر إسهام الرتبة الأولى في قائمة واحدة.

## ٥) البيانات الوصفية: تصفية قبل البحث

| الحقل | الاستخدام |
|---|---|
| `status` · `is_repealed` | **تصفية افتراضية إلزامية** |
| `law_id` · `doc_type` | حصر البحث في نظام أو نوع |
| `parent_law_id` | جلب اللائحة مع نظامها |
| `article_no` | استدعاء مادة بعينها |
| `instrument_no` · التواريخ | العرض والاستشهاد |
| `id` | مفتاح أساسي فريد |

**التصفية على السريان في طبقة الاسترجاع لا في الواجهة.** الشرط مكتوب في SQL داخل `lib/legal.ts`:

```
is_repealed = 0 AND status IN ('active','amended')
```

فأيّ نداء — من محادثة أو تقرير أو أتمتة أو واجهة برمجية — يمرّ به. ولو تُرك للواجهة لتجاوزه أوّل مسار آخر واستشهد بمادة منسوخة.

والشرطان معاً لا أحدهما: من رفع الملف قد يكتب `is_repealed: true` وينسى `status` أو العكس، وأيّهما قال «منسوخ» كفى لإخراج المادة. مادةٌ غائبة أهون من مادة منسوخة يُستشهد بها.

**والمنسوخة تُخزَّن وتُفهرس ولا تُحذف** — الإسقاط عند الاسترجاع لا عند الكتابة. يفتحها `include_repealed=1` للأرشيف والمقارنة التاريخية وحدهما.

و`amended` سارية: نظامٌ عُدِّل وما زال قائماً، فيبقى قابلاً للاستشهاد.

## المسارات

| المسار | الصلاحية | |
|---|---|---|
| `POST /api/legal/import` | مسؤول | استيراد JSONL. `?partial=1` لقبول الصالح. `?filename=` للسجل |
| `POST /api/legal/embed-pending` | مسؤول | تصريف ما ينتظر التضمين. `?limit=` |
| `GET /api/legal/stats` | مسؤول | عدد المقاطع والسارية والمنسوخة والمعلّق تضمينه |
| `GET /api/legal/imports` | مسؤول | آخر دفعات الاستيراد وتقاريرها |
| `GET /api/legal/search` | الجميع | `q` · `law_id` · `doc_type` · `article_no` · `limit` · `with_regulations=0` · `include_repealed=1` |
| `GET /api/legal/article` | الجميع | `?id=` أو `?law_id=&article_no=` |
| `GET /api/legal/laws` | الجميع | الأنظمة المستوردة وعدد مواد كلٍّ منها |
| `GET /api/legal/laws/:lawId` | الجميع | النظام مع لوائحه |

## التشغيل

```bash
# استيراد ملف كامل على دفعات (٥٠٠ سطر لكل طلب)
npm run import:legal -- --file laws.jsonl --url https://advisor.naflaw.sa --cookie "naf_session=…"

# دفعة واحدة مباشرةً
curl -X POST https://advisor.naflaw.sa/api/legal/import \
     -H 'content-type: application/x-ndjson' \
     -H 'cookie: naf_session=…' \
     --data-binary @batch.jsonl
```

الجلسة من الدخول الموحّد: انسخ كوكي `naf_session` من متصفّح حسابٍ مسؤول.

```bash
npm run db:migrate          # محليًا
npm run db:migrate:remote   # على Cloudflare
npm run check:legal         # فحص العقد على الكود نفسه
```

> **نسخ احتياطي:** وجود جدول افتراضي (FTS5) في القاعدة يمنع `wrangler d1 export`. النسخ الاحتياطي عندئذٍ عبر Time Travel.
