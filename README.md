# منصة «مستشار ناف» ⚖️

منصّة استشارات قانونية ذكية باللغة العربية تُنتج **مسوّدات عمل** (صحيفة دعوى، مذكرة رد، عقد، لائحة، رأي قانوني…) بالاعتماد على قاعدة معرفة نظامية سعودية (RAG) ومحرّك توليدي (Claude)، مبنيّة بالكامل على منظومة Cloudflare.

> **مبدأ حاكم:** كل مخرجات المنصّة مسوّدات مساعِدة تخضع لمراجعة محامٍ بشري قبل الاعتماد.

هذا المستودع هو تنفيذ وثيقة المواصفات `nafadvisorplatformspec.md` عبر مراحلها السبع.

---

## نظرة معمارية

```
                         ┌───────────────────────────┐
   المتصفّح (RTL SPA) ───▶│  Cloudflare Worker (Hono) │
   React + Vite          │  المصادقة · التوجيه · SSE  │
                         └────────────┬──────────────┘
                                      │
        ┌──────────────┬─────────────┼──────────────┬───────────────┐
        ▼              ▼             ▼               ▼               ▼
      D1            R2          Vectorize        Workers AI      Claude API
   (بيانات)      (ملفات)      (RAG متجهي)     (تضمين bge-m3)   (تخطيط/توليد
                                                                + web_search)
        ▲                                                            
        │  Queue (تضمين دفعي) · Cron (تتبّع الأنظمة) · KV (جلسات/حدود المعدّل)
```

**تدفّق المحادثة (§5):** رسالة المستخدم → **المُخطِّط** (نموذج خفيف يُنتج خطة JSON) → **المُنفِّذ** (استرجاع RAG + بحث إنترنت + قراءة المرفقات) → تجميع البرومبت مع توجيه النوع → **التوليد المتدفّق** (نموذج قوي) → تنسيق وتصدير.

## التشغيل محليًا

```bash
# 1) تثبيت الاعتماديات
npm install
npm --prefix web install

# 2) إعداد الأسرار المحلية
cp .dev.vars.example .dev.vars   # ثم عدّل ANTHROPIC_API_KEY و JWT_SECRET

# 3) تهيئة قاعدة البيانات المحلية
npm run db:migrate
npm run seed                     # اختياري: بذر قائمة الأنظمة الأولية

# 4) بناء الواجهة ثم تشغيل الـ Worker (يقدّم الواجهة + الـ API)
npm run build:web
npm run dev                      # http://localhost:8787
```

للتطوير مع إعادة التحميل الحيّ للواجهة: شغّل `npm run dev` (Worker على 8787) و`npm run dev:web` (Vite على 5173 مع وكيل للـ API) في طرفيتين.

> **ملاحظة:** `Vectorize` و`Workers AI` لا تعملان في وضع `--local` (يظهران "not supported")؛ لاختبار RAG والتضمين فعليًا استخدم `wrangler dev --remote` أو النشر. تعمل المصادقة والمحادثات ورفع الملفات والتصدير محليًا.

## النشر إلى Cloudflare

### الطريقة السريعة (سكربت موحّد)

```bash
npx wrangler login                 # مرّة واحدة (يفتح المتصفّح)
bash scripts/setup-cloudflare.sh   # يُنشئ D1/R2/Vectorize×2/KV/Queue ويحدّث wrangler.toml
npx wrangler secret put ANTHROPIC_API_KEY
npx wrangler secret put JWT_SECRET # مثال لتوليد قيمة: openssl rand -hex 32
npm run deploy
```

### يدويًا (تفصيليًا)

```bash
wrangler d1 create naf_legal                                            # ← ضع database_id في wrangler.toml
wrangler r2 bucket create naf-legal-files
wrangler vectorize create naf-legal-kb   --dimensions=1024 --metric=cosine
wrangler vectorize create naf-legal-conv --dimensions=1024 --metric=cosine
wrangler kv namespace create KV                                         # ← ضع id في wrangler.toml
wrangler queues create naf-legal-ingest

wrangler secret put ANTHROPIC_API_KEY
wrangler secret put JWT_SECRET

npm run db:migrate:remote
npm run deploy
```

> بُعد المتجهات `1024` مطابق لنموذج `@cf/baai/bge-m3`.

### النشر التلقائي (GitHub Actions)

يوجد `/.github/workflows/deploy.yml` ينشر عند كل دفع إلى `main`. أضِف في إعدادات المستودع سرّين:
`CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` (أسرار الـ Worker تُضبط مرّة واحدة عبر `wrangler secret put`).

### نموذج الحسابات وتسجيل الدخول

- عند أول تشغيل: افتح الموقع وأنشئ **حساب المسؤول الأول** (متاح فقط عندما تكون قاعدة المستخدمين فارغة؛ بعدها يُغلق التسجيل الذاتي).
- المسؤول يضيف بقية المستخدمين من **لوحة الإدارة › المستخدمون** (البريد + الدور). كلمة المرور الافتراضية لأي حساب جديد: **`1234`**.
- عند أول دخول للمستخدم بكلمة `1234`، يُطلب منه **تعيين كلمة مرور جديدة** تُحفظ في قاعدة البيانات، فيدخل بعدها دائمًا بالبريد وكلمة المرور الجديدة.
- يستطيع المسؤول **تصفير** كلمة مرور أي مستخدم إلى `1234` (فيُطلب منه تغييرها مجددًا) أو حذف الحساب.

## القرارات المتّخذة (§14)

قابلة للتعديل — تغييرها موضعي:

1. **المصادقة:** JWT مخصّص مُخزَّن كـ `httpOnly cookie` مع تجزئة `PBKDF2-SHA256` (متاح أصلًا في Workers دون اعتماديات). يمكن إضافة `Cloudflare Access` للمسؤولين لاحقًا.
2. **إطار الواجهة:** `Vite + React` (SPA خفيف) — أبسط وأخف على Workers Assets من Next.js.
3. **نطاق البحث في الإنترنت:** المستخدم يتحكّم عبر مُبدّل؛ عند تفعيله يدويًا يكون مفتوحًا، وفي مهام تتبّع الأنظمة (Cron) يُقيَّد تلقائيًا بالمصادر الرسمية عبر `allowed_domains`.
4. **طبقات النماذج:** المُخطِّط والتصنيف والاستخراج على `Haiku`؛ التوليد النهائي على `Sonnet` (يُضبطان في `[vars]` بـ `wrangler.toml`). حدّ معدّل 60 طلب/دقيقة لكل مستخدم عبر KV.
5. **قائمة الأنظمة الأولية:** المرافعات الشرعية · المعاملات المدنية · العمل · الشركات · الإثبات · الجمعيات (تُبذر عبر `npm run seed`، ثم يرفع المسؤول الوثائق الرسمية).
6. **توطين البيانات:** `DATA_REGION` في `wrangler.toml`؛ راجِع خيارات `Jurisdictional Restrictions` في D1/R2 لأي اشتراط بالتوطين.

## الأمان والخصوصية (§12)

- **العزل:** كل استعلام على المحادثات والملفّات مقيّد بـ `user_id`؛ لا يرى مستخدم بيانات غيره.
- **سجل التدقيق:** كل فعل إداري (رفع/حذف نظام، تغيير دور، اعتماد تحديث) يُسجَّل مع الفاعل والوقت.
- **حدود المعدّل:** عبر KV لمنع الإساءة والتحكّم في التكلفة.
- **ترويسات أمان:** عبر `secureHeaders` من Hono.
- **إخلاء مسؤولية ثابت:** في واجهة كل محادثة وفي تذييل كل مخرَج Word.
- **PDPL:** التشفير في النقل والتخزين مُفعَّل افتراضيًا على Cloudflare؛ لتوطين البيانات راجِع القيود الاختصاصية لـ D1/R2. الأسرار عبر `wrangler secret` لا في المستودع.

## استيراد المحتوى النظامي

مصدران يغذّيان قاعدة المعرفة:

**١) وثائق تُرفَع** (PDF/Word/نص) فيستخرج منها النصّ ويقطّعه المُستوعِب — لأن لا أحد قطّعها قبلنا.

**٢) مقاطع تُستورَد** بعقد `JSONL`: سطر مستقل لكل مادة، مقطوعةً سلفاً بحدودها الصحيحة. **والتقطيع التلقائي معطَّل في هذا المسار** — إعادة تقطيعها تقصّ في منتصف المواد بلا وعي بحدودها.

```bash
npm run import:legal -- --file laws.jsonl --url https://advisor.naflaw.sa --cookie "naf_session=…"
npm run check:legal   # فحص العقد على الكود نفسه
```

أربعة التزامات يقوم عليها العقد:

| | |
|---|---|
| **الاستيراد** | سطر = مقطع · UTF-8 بلا BOM · **استبدال (`upsert`) على `id` لا إضافة** |
| **الفهرسة** | `embed_text` وحده يصير متجهاً · `text` وحده يُعرض ويُستشهد به |
| **البحث** | دلاليّ + لفظيّ مدموجان · تطبيع عربي (الهمزات، التاء المربوطة، الألف المقصورة، التشكيل، التطويل) |
| **التصفية** | السريان (`status` · `is_repealed`) **في طبقة الاسترجاع لا في الواجهة** — فلا يتجاوزها تقرير ولا أتمتة ولا واجهة برمجية |

التفصيل والحقول والمسارات في **[`docs/legal-import.md`](docs/legal-import.md)**.

## المخرجات القابلة للتصدير

- **Word (.docx):** يُولَّد أصلًا داخل الـ Worker (كاتب ZIP + CRC32 مضمّن) بتنسيق عربي RTL، خط معقّد، وتذييل إخلاء المسؤولية — دون اعتماديات خارجية. يدعم **رأسية الشركة** (صورة A4 يرفعها المسؤول من الإعدادات).
- **PDF:** عبر طباعة المتصفّح (يدعم العربية أصلًا).
- **نص (.txt):** نسخ مباشر أو تنزيل.

## الإضافات المتقدّمة

بُنيت خمس مجموعات إضافية فوق الأساس:

**1) الجوهر القانوني**
- **مراجعة/تدقيق المستندات:** نوع استشارة يحلّل المخاطر بندًا ببند مع صياغات بديلة.
- **مقارنة نسختين (diff قانوني):** إبراز الفروق وأثرها (`/api/tools/compare`).
- **حاسبة المواعيد النظامية:** من تاريخ التبليغ إلى مواعيد الاعتراض/الاستئناف.
- **الاقتباس المُتحقَّق منه:** منع ذكر مواد غير مسنودة في قاعدة المعرفة.

**2) الموثوقية**
- **طبقة تحقّق بعد التوليد:** نموذج ثانٍ يؤكّد إسناد كل مادة إلى السياق المسترجَع، وتظهر النتيجة كشارة على المخرَج.
- **قوالب Word برأسية الشركة** + **تقييم الردود** (👍/👎).

**3) الإنتاجية**
- **مشاركة المسودّة مع محامٍ:** رابط عام برمز، تعليقات، اعتماد/طلب تعديل، وسجل نُسخ (`/review/:token`).
- **مجلدات ووسوم للقضايا** · **بحث دلالي في السجل** (Vectorize مع رجوع نصّي) · **إدخال صوتي عربي** (Whisper عبر Workers AI).

**4) الأعمال**
- **لوحة تحليلات:** الاستهلاك والتكلفة حسب العملية/النوع/المستخدم.
- **مخرجات ثنائية اللغة** (عربي/إنجليزي) · **تصدير PDF**.

**5) قاعدة المعرفة**
- **إصدارات الأنظمة:** أرشفة النص القديم بتواريخ سريان عند رفع نسخة أحدث.
- **خلاصة أخبار جريدة أم القرى** (Cron) + **استيعاب تلقائي** لعنصر عند اعتماده.

**6) قراءة المحادثة**
- **تحديد النصّ وتظليله:** أيّ نصّ في المحادثة — رسالة المستخدم أو ردّ المساعد — يُحدَّد فيظهر شريطٌ فوقه: نسخ · تظليل · مسح التظليل · اقتباس. والتظليل يُحفَظ بإزاحتين على نصّ الرسالة (`message_highlights`) ومعه مقتطعٌ شاهد يُقابَل به الموضع، فتظليلٌ على جملةٍ أُزيحت بتحرير المسوّدة يسقط ولا يقع على غيرها. و«اقتباس» ينقل المحدَّد إلى صندوق الكتابة. و«مستخدم (اطّلاع)» له النسخ وحده — التظليل كتابة.
- **المصادر تُفتح لا تُذكَر:** شارة المصدر أسفل الردّ زرٌّ يفتح المادة بنصّها النافذ، وأداةِ إصدار نظامها وجهتِه وتاريخِه، وتنبيهاتِها، وسجلِّ تعديلاتها، وزرِّ الانتقال إلى صفحتها في بوابة هيئة الخبراء. والمادة تُجلب عند كل فتحة لا تُقرأ من الاستشهاد المحفوظ: النافذ اليوم قد يكون غير ما استُند إليه يومها. واستشهادات المحادثات القديمة — حُفظت بعنوان النظام ورقم المادة وحدهما — تُفتح بمطابقة العنوان مطابقةً تامّة (`/api/legal/article?law_title=&article_no=`)، وما لم يُطابق يبقى شارةً ولا يُفتح تخميناً.
- **التوليد يعمل في الخلفية:** الدور صار مهمّةً في `waitUntil` لا جسماً داخل مجرى الاستجابة، فإغلاق التبويب أو إعادة تحميل الصفحة لا يقطعه — والردّ والعنوان وتحقّق الإسناد تُحفَظ على أي حال. وفي الواجهة يعيش البثّ في `web/src/lib/chatStream.ts` خارج شاشة المحادثة، فتبديل المحادثة أو فتح الأدوات لا يهدمه ولا يفقد ما وصل منه. ومن عاد بعد إعادة التحميل تقول له علامةٌ في KV (`src/lib/generating.ts`) إن ثمّة دوراً يجري، فينتظره ولا يعيد السؤال.

> جميعها موثّقة في مخطط `migrations/0003_features.sql` و`migrations/0019_message_highlights.sql`، والمسارات تحت `src/routes/`.
